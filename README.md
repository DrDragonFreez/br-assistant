# Интеллектуальный помощник по внутренним регламентам

Локальный помощник, который отвечает на вопросы по внутренней Инструкции по
документационному обеспечению управления **со ссылкой на конкретный пункт**,
формирует проекты документов по утверждённым модулям и проверяет готовые
проекты на соответствие требованиям.

Весь стек — открытые решения, развёртывание локальное. **Ни один фрагмент
внутреннего документа не уходит во внешние сервисы**: языковая модель,
эмбеддинги и реранкер работают внутри контура.

Прототип для хакатона «Финтех Хаб» Банка России, Junior-трек.

## Что потребуется

| | Минимум | Комментарий |
|---|---|---|
| Docker | Desktop 4.30+ / Engine 26+ | с поддержкой Compose v2 |
| Видеопамять | 8 ГБ | модель занимает ≈7 ГБ. Нет видеокарты — `make up-cpu` |
| Оперативная память | 10 ГБ виртуальной машине Docker | на Windows см. [настройку WSL2](#памяти-не-хватает) |
| Диск | 25 ГБ | образы ≈3 ГБ, веса моделей ≈11 ГБ |
| Интернет | только на первый запуск | для загрузки весов моделей |

`make` не обязателен: ниже для каждой цели приведена равнозначная команда.

### Материалы кейса

Каталоги `data/instructions/` и `data/templates/` **вне репозитория** — в них
лежат материалы кейса. Перед запуском положите туда:

```
data/instructions/   Инструкция по ДОУ (PDF), Матрица обязательного визирования
                     и Методические рекомендации по модульным документам (DOCX)
data/templates/      семь файлов модулей документов от организаторов (DOCX)
```

Без них контур поднимется, но база знаний будет пустой, и помощник на каждый
вопрос честно ответит, что данных нет.

## Запуск

Семь шагов. Все команды проверены на этом контуре; порядок существенен.

```bash
# 1. Окружение: секреты генерируются и подставляются во все связанные переменные
make env                       # python scripts/init_env.py

# 2. Образы
make build                     # docker compose build --parallel

# 3. Модели: загрузка qwen2.5-7b и bge-m3, сборка br-assistant из Modelfile
make models                    # docker compose up --exit-code-from ollama-init ollama-init

# 4. Контур. Миграции применяются автоматически при старте бэкенда
make up                        # docker compose up -d

# 5. Бланки документов из модулей кейса
make templates                 # docker compose exec -T backend python scripts/build_templates.py

# 6. Администратор, демо-пользователи, реестр бланков
make seed                      # docker compose exec -T backend python -m app.db.seed

# 7. Индексация базы знаний
make index                     # docker compose exec -T backend python -m app.workers.cli reindex
```

Шаг 3 занимает больше всего времени: это 11 ГБ весов. Шаги 5–7 требуют
поднятого контура — они выполняются внутри контейнера, где есть зависимости.

Нет видеокарты NVIDIA — на шаге 4 вместо `make up` используйте `make up-cpu`
(`docker compose -f docker-compose.yml -f docker-compose.cpu.yml up -d`).

### Проверка

```bash
make smoke                     # ./.venv/Scripts/python.exe scripts/smoke_test.py
```

Скрипт проходит контур целиком и печатает результат каждой проверки:

```
✓ вход выполнен: admin@cbr.local
✓ профиль получен: роль admin, прав 17, грифы ['public', 'internal', 'confidential']
✓ ответ получен: 115 знаков, источников 5, релевантность 82%, 8016 мс
✓ ответ содержит ссылку на пункт инструкции
✓ первый источник: п. ['10.3'], с. 42
✓ вердикт критика: approved
✓ на вопрос вне базы знаний получен честный отказ
✓ бланков документов: 7
✓ состояние контура: ok
```

Зависимостей у проверки нет — только стандартная библиотека Python, поэтому
она запускается на машине без собранного окружения. Логин и пароль берутся
из `.env`. Make вызывает Python из `.venv`, а если его нет — `python3`: на
Windows `python` в PATH бывает заглушкой Microsoft Store, которая ничего не
запускает.

## Как получается ответ

### Ссылка на конкретный пункт

Инструкция режется не по символам, а по границам пунктов
(`backend/app/rag/chunker.py`): фрагмент знает свой номер пункта, раздел,
приложение и страницу. Из 261 фрагмента номер пункта несут 259 — остальные два
приходятся на преамбулу, у которой номера нет.

Подсказка требует ссылку после каждого утверждения, а
`generator.extract_citations()` позволяет проверить ссылки программно, не
доверяя модели на слово.

### Три барьера против выдумывания

1. **До генерации.** Если лучший найденный фрагмент не дотягивает до
   `ANSWER_MIN_RELEVANCE`, модель не вызывается вовсе — выдаётся отказ.
2. **В подсказке.** Модель обязана вернуть маркер `НЕТ_В_БАЗЕ_ЗНАНИЙ`, если
   контекста недостаточно.
3. **После генерации.** Критик (`backend/app/agents/critic.py`) сверяет каждый
   упомянутый номер пункта с теми, что реально были в контексте. Ссылка на
   несуществующий пункт отлавливается операцией над множествами, без участия
   модели.

На эталонном наборе из 57 вопросов выдуманных ответов — ни одного.

### Разграничение доступа

Четыре роли и три грифа документов. Фильтр по грифу уходит **в сам запрос к
Qdrant**: закрытые для роли положения не попадают даже в контекст языковой
модели. Это свойство устройства, а не договорённость в подсказке.

### Проверка готового проекта

Вкладка «Проверка» принимает `.docx`, `.pdf`, `.txt`, `.md` до 50 МБ. Файл
разбирается, проверяется и удаляется — на диске он не остаётся. Проверка
двухслойная (`backend/app/services/doc_validator.py`):

- **Детерминированные правила.** Обязательные реквизиты; незаполненные поля
  модуля — поля шаблона `{{ … }}` и прочерки [Методические рекомендации,
  п. 3.2]; служебные элементы, которые исполнитель удаляет после заполнения:
  пометка «МОДУЛЬНЫЙ ДОКУМЕНТ», гриф «УТВЕРЖДАЮ», блок примечаний, номера
  примечаний, невыбранные варианты в скобках [п. 3.3].
- **Смысловая сверка моделью** с найденными положениями. Замечание модели
  остаётся, только если процитированный пункт действительно говорит о
  поле: ссылка на существующий пункт ещё не делает требование верным.

Дата, регистрационный номер и подпись в проекте ещё не проставлены по
определению — их ставят при подписании и регистрации [п. 10.1, 7.1]. Они
выводятся отдельным списком и на оценку не влияют. Под отчётом для приказов
и распоряжений — порядок дальнейших действий: согласование, сроки,
таблица замечаний, визирование, подписание, регистрация со ссылками на
пункты Инструкции.

### Редакции базы знаний

Новая редакция индексируется рядом со старой; действующая всегда ровно одна
(частичный уникальный индекс в PostgreSQL плюс признак `is_active_version` в
payload Qdrant). Откат выполняется одной командой, без переиндексации
остальных документов.

## Сетевой контур

Два моста Docker:

- **`br_net`** (`internal: true`) — PostgreSQL, Redis, Qdrant. Наружу не
  выставлен ни один порт, выхода в интернет у этих сервисов нет вовсе.
- **`br_edge`** — Nginx (единственный опубликованный порт), интерфейс, API,
  Ollama и реранкер. Последним двум интернет нужен только на первую загрузку
  весов; в закрытом контуре веса приносятся отдельно, и `br_edge` у них
  снимается.

Что ещё сделано для требований информационной безопасности: маскирование ФИО,
адресов и номеров документов в журналах; отзыв токенов через список в Redis;
журнал аудита по всем действиям с документами; эндпоинт метрик закрыт на
обратном прокси. Подробно — `docs/security_rbac.md`.

## Оценка качества

```bash
make eval ARGS=--skip-ragas    # собственные метрики, около 7 минут
make eval                      # вместе с метриками RAGAS, заметно дольше
```

Прогон на 57 вопросах эталонного набора (`data/eval_set/golden.jsonl`), все
номера пунктов проверены по тексту Инструкции:

| Метрика | Значение |
|---|---|
| Выдуманных ответов на вопросы вне базы знаний | **0.000** |
| Процитирован именно ожидаемый пункт | 0.961 |
| Процитированные пункты относятся к вопросу | 0.951 |
| Корректность поведения при отсутствии данных | 0.965 |
| Ответов, одобренных критиком | 0.891 |
| Средняя задержка полного контура | 6,1 с |

Разбор по категориям вопросов, история доводки с цифрами по каждой правке и
три проверенные гипотезы — одна принятая и две отклонённые — в
`docs/ragas_report.md`.

### Про задержку

Замеры на NVIDIA RTX 4060 Laptop, 8 ГБ видеопамяти, на незанятой карте. На
один вопрос приходится три обращения к модели — классификация обращения,
генерация, проверка критиком, — поэтому 6,1 с. Под нагрузкой (одновременно
идёт проверка документа или второй прогон оценки) задержка доходит до 12 с:
обращения состязаются за одну видеокарту. Потоковая выдача `POST /chat/stream` начинает печатать сразу:
критика в ней нет по построению. Повтор того же вопроса приходит из кеша
мгновенно, и в интерфейсе появляется отметка «из кеша». Первый запрос после
старта дольше примерно на минуту: Ollama загружает модель в память.

## Перед показом

1. `make ps` — все сервисы `healthy`.
2. `make warmup` за 10–15 минут до выступления: ответы живут в кеше час, и
   на показе они приходят мгновенно и без разброса. После перезапуска
   Docker кеш пуст — прогрев обязателен.
3. В браузере `Ctrl+Shift+R` после каждой пересборки фронтенда.
4. Во время записи не запускать `make eval`: прогон загружает видеокарту и
   память, задержка ответов вырастает в разы, а при лимите WSL2 в 10 ГБ
   Docker может остановиться целиком.

Для показа проверки документа удобна пара файлов: пустой бланк
`data/templates/MOD-ORDER-IS-DEPLOY.docx` (существенные замечания,
незаполненные поля) и черновик, собранный по нему в диалоге (соответствует).

## Расхождения с исходным замыслом

Пять мест, где реализация отличается от первоначального стека. Каждое —
осознанное решение.

1. **Проверка токена в Nginx.** Директива `auth_jwt` доступна только в
   NGINX Plus (коммерческая лицензия), что противоречит требованию открытого
   кода. Nginx отвечает за ограничение частоты, TLS и заголовки безопасности;
   подпись токена, срок жизни и права роли проверяет FastAPI через
   `python-jose`.
2. **Одна модель эмбеддингов.** В исходном стеке упоминались и bge-m3, и
   nomic-embed-text. Оставлена bge-m3: мультиязычная, лучше на русском
   нормативном тексте, даёт разреженные векторы для гибридного поиска.
   Смешивать две модели в одной коллекции нельзя — векторы несопоставимы.
3. **Реранкер отдельным сервисом.** У Ollama нет эндпоинта реранка, только
   генерация и эмбеддинги, поэтому bge-reranker-v2-m3 поднят сервисом Infinity.
4. **Критик и потоковая выдача несовместимы.** Проверка требует второго вызова
   модели уже после того, как текст сформирован; стримить текст, который критик
   может отклонить, бессмысленно. В `POST /chat/stream` работает барьер по
   релевантности до генерации, полный контур с критиком — в `POST /chat`.
5. **Дообучения модели нет.** `ml/modelfiles/Modelfile` собран
   `FROM qwen2.5:7b-instruct`; GGUF со слитым адаптером не создавался,
   обучающего набора и весов в проекте нет. Модель `br-assistant` отличается от
   базовой только закреплёнными параметрами генерации: температура 0.1 ради
   воспроизводимости и стоп-последовательности, не дающие модели продолжить
   диалог за сотрудника. Конвейер (`ml/synth_dataset.py` → `ml/train_lora.py` →
   `ml/export_gguf.py`) подготовлен и запускается отдельно.

   Прогон эталонного набора на обеих моделях дал разницу в один вопрос из 57 —
   то есть внутри разброса между запусками, при совпадающей до четвёртого знака
   релевантности поиска. Качество в этой задаче определяет работа с источниками,
   а не генератор.

## Если что-то не работает

### Памяти не хватает

Признак специфичный: контейнеры числятся запущенными, но любая команда к Docker
отвечает `500 Internal Server Error` — ядро сняло процессы демона. На Windows
WSL2 по умолчанию забирает половину памяти хоста, и этого мало. Создайте
`%USERPROFILE%\.wslconfig`:

```ini
[wsl2]
memory=10GB
processors=6
swap=6GB
autoMemoryReclaim=gradual
```

Затем `wsl --shutdown` и запустите Docker Desktop заново.

Второй вариант того же: Docker Desktop закрывается сам, а `docker ps`
отвечает `failed to connect to the docker API`. Так бывает, если во время
работы контура запустить тяжёлый прогон — `make eval` на 57 вопросов.
Запустите Docker Desktop: контейнеры поднимутся сами, данные в томах
сохраняются. Затем `make warmup` — кеш ответов после перезапуска пуст.

### Реранкер не поднимается

Он и не должен при обычном запуске: сервис объявлен за профилем Compose.
qwen2.5-7b занимает ≈5,5 ГБ видеопамяти, bge-m3 — ещё ≈0,7 ГБ, и на карте с
8 ГБ для bge-reranker-v2-m3 (≈2,5 ГБ) места не остаётся. Граф при этом
переходит на MMR-переранжирование и продолжает работать, качество поиска ниже.
Карта от 12 ГБ — `RERANKER_ENABLED=true` в `.env` и `make up-rerank`.

### Загрузка моделей падает с ошибкой сертификата

```
x509: certificate signed by unknown authority
```

Антивирус с перехватом TLS (Kaspersky, ESET, корпоративный прокси) подменяет
сертификат. Экспортируйте его корневой сертификат и добавьте в контейнер:

```bash
docker cp root-ca.crt br_ollama:/usr/local/share/ca-certificates/
docker compose exec ollama update-ca-certificates
docker compose restart ollama
```

### `make seed` сообщает, что таблиц нет

Миграции применяет бэкенд при старте (`RUN_MIGRATIONS=1`). Если контейнер не
успел их выполнить или падал, примените вручную: `make migrate`.

### Индексация сообщает, что файлов нет

Проверьте, что материалы кейса лежат в `data/instructions/` — каталог вне
репозитория. Если вы передаёте путь вручную из Git Bash на Windows, аргумент,
начинающийся со слеша, переписывается в путь Windows: `/app/data/instructions`
превращается в `C:/Program Files/Git/app/data/instructions`. Команды из этого
README путей не передают — каталог берётся из `INSTRUCTIONS_DIR`. Если путь всё
же нужен, добавьте `MSYS_NO_PATHCONV=1` перед командой.

### Вход возвращает 422

Адрес не прошёл проверку схемы. Учётные записи контура живут в зоне `.local`,
которую библиотека проверки адресов считает зарезервированной; разрешение этой
зоны задано в `app/core/config.py`. Если меняли домен — проверьте, что новая
зона не входит в список особых (`arpa`, `invalid`, `onion`, `test`).

### Образ бэкенда собирается слишком долго

`ragas` и `datasets` добавляют к образу около 400 МБ. Уберите эти две строки из
`backend/requirements.txt` — они продублированы в `requirements-eval.txt` — и
запускайте оценку отдельным контейнером.

## Структура

```
backend/app/
├── core/       конфигурация, безопасность, права ролей, журналирование, метрики
├── db/         модели, PostgreSQL, Redis, Qdrant, каталог модулей, стартовые данные
├── rag/        загрузка, нарезка, эмбеддинги, BM25, поиск, реранк, генерация, редакции
├── agents/     граф LangGraph: состояние, маршрутизатор, уточнения, критик, сборка документа
├── services/   реестр бланков, генерация DOCX, проверка документов, индексация, оценка
├── workers/    Celery: приложение, задачи, расписание, командная строка
└── api/v1/     схемы, зависимости, health, auth, chat, documents, admin, metrics

frontend/       Next.js 14: страницы диалога, бланков и администрирования
infra/          Nginx, Prometheus, Grafana
ml/             генерация обучающего набора, дообучение, выгрузка GGUF, Modelfile
scripts/        подготовка окружения, сборка бланков, сквозная проверка
data/           материалы кейса и эталонный набор вопросов (вне репозитория)
```
