# Архитектура решения

## Обзор

Интеллектуальный помощник по внутренним регламентам построен как набор
контейнеризованных сервисов, разворачиваемых локально одной командой.
Весь контур работает на open source: языковая модель, эмбеддинги и
реранкер исполняются внутри периметра, обращений во внешние API нет.

```
                    ┌─────────────────────────────────┐
                    │   Сотрудник (браузер / виджет)  │
                    └───────────────┬─────────────────┘
                                    │ HTTPS
                    ┌───────────────▼─────────────────┐
                    │  Nginx — rate-limit, TLS, SSE   │   контур br_edge
                    └───────┬───────────────┬─────────┘
                            │               │
            ┌───────────────▼──┐      ┌─────▼──────────────┐
            │  Next.js 14      │      │  FastAPI           │
            │  shadcn/ui, SSE  │      │  JWT + RBAC        │
            └──────────────────┘      └─────┬──────────────┘
                                            │
                        ┌───────────────────┴───────────────────┐
                        │        LangGraph (оркестрация)        │
                        │  Router → Retriever → Reranker →      │
                        │  Generator → Critic → DocBuilder      │
                        └───────────────────┬───────────────────┘
                                            │
   ┌────────────┬────────────┬──────────────┼────────────┬──────────────┐
   │            │            │              │            │              │
```

## Стек реализации

| Компонент | Технология | Обоснование выбора |
|---|---|---|
| Обратный прокси | Nginx 1.27 | rate-limit по зонам, отключение буферизации для SSE, лимит загрузки 50 МБ |
| Интерфейс | Next.js 14 (App Router), shadcn/ui | серверные компоненты, потоковый вывод, готовые доступные компоненты |
| API | FastAPI, Pydantic v2, SQLAlchemy 2 (async) | полностью асинхронный стек, автодокументация OpenAPI |
| Оркестрация | LangGraph | явный граф с условными переходами и циклом самопроверки |
| Векторный поиск | Qdrant 1.12 | нативная поддержка гибридного поиска и слияния RRF на стороне БД |
| Эмбеддинги | bge-m3 (1024) | мультиязычная модель, устойчивая к русскому нормативному стилю |
| Переранжирование | bge-reranker-v2-m3 | cross-encoder заметно точнее bi-encoder на близких формулировках |
| Языковая модель | Qwen2.5-7B-Instruct | лучшее качество на русском среди моделей, помещающихся в 1 GPU. Модель `br-assistant` собрана из неё Modelfile-ом: закреплены температура, окно контекста и стоп-последовательности. Конвейер дообучения (`ml/`) подготовлен, но адаптер не обучен и в контур не входит |
| Состояние | PostgreSQL 16, Redis 7 | реляционные данные и версионность / кеш и временное состояние |
| Фоновые задачи | Celery (worker + beat) | индексация и оценка качества занимают минуты, HTTP их не держит |
| Наблюдаемость | Prometheus + Grafana | доменные метрики качества ответов, а не только латентность |

## Точки входа

Наружу Nginx отдаёт только то, что начинается с `/api/`, и интерфейс.
Всё остальное достижимо лишь внутри контура — это не настройка, а часть
разграничения доступа.

| Адрес | Назначение |
|---|---|
| `http://localhost/` | интерфейс сотрудника |
| `http://localhost/api/v1/...` | API: диалог, документы, база знаний |
| `http://localhost/api/v1/docs` | Swagger — документация и ручные запросы |
| `http://localhost/grafana/` | дашборд качества и нагрузки |
| `backend:8000/metrics` | метрики Prometheus, **только из сети `br_net`** |
| `backend:8000/health/ready` | readiness-проба для оркестратора |

Префикс версии API не срезается прокси, поэтому `root_path` приложения
пустой: Starlette вырезает `root_path` из пути до сопоставления маршрута,
и непустое значение в паре с `/api/v1` отдавало бы 404 на всё API.
Конфигурация с таким конфликтом не даст сервису запуститься — проверка
в `Settings` падает на старте.

Проверки состояния и метрики подключены в корень приложения, а не в роутер
версии: первые опрашивает docker healthcheck, вторые — Prometheus по
внутренней сети. Для экрана администратора есть авторизованный
`GET /api/v1/admin/system/health` — тот же состав проверок, но с правом
`metrics:read`.

## Граф обработки обращения

Каждое обращение проходит через граф LangGraph. Ветвление определяется
намерением, выявленным маршрутизатором.

1. **Router** — классифицирует обращение. Сначала быстрые правила
   (воспроизводимо, без вызова модели), при неоднозначности — языковая
   модель в режиме структурированного вывода.
2. **Clarifier** — задаёт уточняющий вопрос, если без него нельзя
   определить применимые требования.
3. **Retriever** — гибридный поиск. Если в запросе есть прямая ссылка на
   пункт, соответствующие фрагменты добавляются в выдачу принудительно.
4. **Reranker** — переранжирование top-20 → top-5 cross-encoder'ом.
   При недоступности сервиса деградирует до MMR на лексическом пересечении.
5. **Generator** — формирует ответ. До вызова модели проверяется
   достаточность контекста.
6. **Critic** — проверяет обоснованность ответа. При отрицательном
   вердикте возвращает управление генератору (одна повторная попытка).
7. **TemplateMatcher / DocBuilder** — подбор бланка и пошаговое заполнение.

## Масштабирование

- **Горизонтально**: FastAPI и Celery-воркеры без состояния, добавляются
  репликами. Состояние целиком в PostgreSQL, Redis и Qdrant.
- **Языковая модель**: Ollama заменяется на vLLM с тензорным параллелизмом
  без изменения кода — интерфейс остаётся HTTP-совместимым.
- **Qdrant**: переводится в кластерный режим с шардированием по документам.
- **Новые источники данных**: подключаются регистрацией документа в базе
  знаний и загрузкой редакции; код не меняется.

## Интеграция с корпоративной средой

- **Аутентификация**: вместо встроенной выдачи токенов перед Nginx
  ставится `oauth2-proxy` или Keycloak с подключением к корпоративному
  каталогу. Проверка прав в приложении остаётся прежней.
- **Виджет для портала**: интерфейс собирается как standalone-страница и
  встраивается в корпоративный портал через iframe либо поставляется как
  всплывающий виджет на том же API.
- **Офлайн-развёртывание**: веса моделей выгружаются заранее, после чего
  сервисам Ollama и reranker снимается доступ в сеть — контур работает
  полностью изолированно.
- **Перехват TLS**: в корпоративной сети трафик обычно расшифровывается
  средством защиты (антивирус, прокси), и сертификат подменяется. Хост
  такому корневому сертификату доверяет, а контейнер — нет: первичная
  загрузка весов падает с `x509: certificate signed by unknown authority`,
  уже скачав файл. Корневой сертификат нужно положить в доверенные
  внутри контейнера:

  ```bash
  docker cp corporate-root.crt br_ollama:/usr/local/share/ca-certificates/
  docker compose exec ollama update-ca-certificates
  docker compose restart ollama
  ```

  Это проверено на практике: загрузка моделей на машине с антивирусным
  перехватом не проходит без этого шага. В изолированном контуре вопрос
  снимается сам — веса приносятся офлайн.
